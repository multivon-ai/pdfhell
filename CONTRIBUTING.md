# Contributing to PDF Hell

Thanks for considering a contribution. PDF Hell is small on purpose — three trap families, ~2k LOC — and we want to keep additions sharp. This guide is short for the same reason.

## Quick rules

- **Procedural ground truth is non-negotiable.** Every trap generator must produce its answer key *from code*. We don't ship traps where the answer comes from an LLM judging another LLM.
- **Deterministic seeds.** Same seed → byte-identical PDF and identical `HellCase`. The test suite enforces this — keep `Canvas(invariant=True)` set and don't depend on the wall clock.
- **Named failure modes.** Every trap should be designed to elicit a *specific* wrong answer. Put that wrong answer in `HellCase.forbidden_answers` and a human-readable description in `metadata["expected_failure_mode"]`. The diagnostic is half the value.

## Adding a new trap family

1. **Create the generator.** Add `pdfhell/generators/<your_trap>.py`:

   ```python
   from reportlab.pdfgen import canvas
   from ..case import HellCase
   from . import _common as C

   def generate(seed: int) -> tuple[bytes, HellCase]:
       rng = C.rng_for(seed)
       # ... use rng for every choice; never call random.* directly ...

       def draw(c: canvas.Canvas) -> None:
           c.setFont("Helvetica", 12)
           c.drawString(72, 720, "Header")
           # ... draw the PDF; use C.draw_paragraph, C.draw_table, etc. ...

       pdf_bytes = C.canvas_to_bytes(draw)
       return pdf_bytes, HellCase(
           id=f"your_trap-{seed:04d}",
           trap_family="your_trap",
           seed=seed,
           question="What is ...?",
           expected_answer="42",
           # If the right answer can be phrased many equally-correct ways,
           # use expected_tokens instead (list of substrings, all required):
           # expected_tokens=["42", "...", "..."],
           forbidden_answers=["41"],  # plausible-but-wrong answer the trap elicits
           metadata={
               "expected_failure_mode": "Model does X when it should do Y.",
           },
       )
   ```

2. **Register it.** In `pdfhell/generators/__init__.py`:

   ```python
   from .your_trap import generate as _your_trap

   GENERATORS: dict[str, GeneratorFn] = {
       # ... existing ...
       "your_trap": _your_trap,
   }
   ```

3. **Add it to the mini suite (optional).** In `pdfhell/suite.py`:

   ```python
   def mini_suite() -> SuiteSpec:
       return SuiteSpec(
           name="mini",
           traps={
               # ... existing ...
               "your_trap": list(range(4001, 4011)),
           },
       )
   ```

4. **Test it.** `pytest tests/test_generators.py` covers the contract (PDF starts with `%PDF-`, regeneration is deterministic, ids change with seeds). Run `pdfhell make --trap your_trap --seed 1 && open cases/your_trap-0001.pdf` and verify the PDF looks the way you expect.

5. **Open a PR.** Keep the change focused — one trap family per PR. Include:
   - The generator file
   - The registration in `__init__.py`
   - (Optional) suite entry
   - A note in the PR description on which specific failure mode this trap catches that the existing three don't

## Reviewing PRs

We look for:

- **Deterministic generation** — `Canvas(invariant=True)`, no wall-clock dependency, all randomness from `rng_for(seed)`.
- **Code-based answer key** — the answer in `HellCase.expected_answer` (or `expected_tokens`) is derived from the same `rng` that drew the PDF.
- **Named failure mode** — `forbidden_answers` contains the wrong value the trap specifically elicits, and `metadata["expected_failure_mode"]` describes the failure in one sentence.
- **PDF integrity** — the generated bytes parse as a valid PDF (`pypdf.PdfReader` doesn't raise).

## Code style

- Python 3.10+
- `from __future__ import annotations` at the top of every module
- Type-hint everything except trivial test helpers
- `ruff` for lint (config in `pyproject.toml`)
- Comments explain *why*, not *what*
